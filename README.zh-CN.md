# clinx — AI-native 全栈研发

clinx 让 Agent 从需求和现有工程出发，完成实现、验证与交接，并让有用经验服务下一次任务。
它提供通用方法论、可移植 Skill 和可选 CLI，不要求更换语言、框架或开发环境。

[English](README.md) · [开始使用](docs/zh-CN/cold-start.md) · [完整案例](docs/zh-CN/hands-on.md) · [文档](docs/zh-CN/README.md)

## 接入一次，直接提需求

按[接入指南](docs/zh-CN/installation.md)让 Agent 使用已审阅的 Skill；团队或宿主已有可用副本时直接复用。
仅使用 Skill 不需要 Node、CLI、工程地图或任务 JSON，也不用逐仓初始化。

接入后可以这样开始：

> 在当前业务上下文中，按 clinx 完成这份 PRD：`<文件或链接>`。
> 先给我确认关键方案，确认后自主实现和验证；不推送、不部署。

已知工程位置从当前任务、知识入口和本地绑定中取得，不必重复提供。
全新宿主没有入口时，补一个工程或知识定位起点即可。
目录迁移和多副本选择见[上下文复用](docs/zh-CN/project-context.md)。

低风险任务可以直接授权实现；只做设计、诊断或评审时明确说明。
Agent 自行调查工程事实、复用已有能力、选择相关工具和验证路径，只在约定确认点或真正缺少决定与权限时询问。
你不必选择工作流模式、图谱工具或填写配置。[范围与授权](docs/zh-CN/collaboration.md)始终适用。

应拿到的不是一句“已完成”，而是可使用的结果：改了什么、如何运行和停止、实际验证了什么、还有什么未完成。
“全栈”覆盖结果所需的边界，不强制每个需求都有页面、API 和数据库。

## 用在什么任务上

| 你的任务           | clinx 如何参与                                   |
| ------------------ | ------------------------------------------------ |
| 从零实现需求       | 澄清必要决定，尽早跑通最小完整链路               |
| 扩展或复用旧系统   | 核对现有语义、规则归属和受影响消费者             |
| 多仓交付           | 在一个协调位置工作，引用各源，不搬迁或逐仓初始化 |
| 中断后继续         | 恢复需求、变化和未决事项，不盲目重放旧操作       |
| 理解或维护工程知识 | 核验来源、纠正旧指南，让下一次任务能找到并复用   |

软件变更由 `clinx-delivery` 指导；独立知识工作使用 `clinx-knowledge`。
两份 Skill 自包含、共用知识规则。宿主按意图选择；不支持自动选择时明确指定对应 Skill。
方法是 **调查 → 约定 → 实现 → 验证 → 沉淀**，不是五道人工审批。

[实操案例](docs/zh-CN/hands-on.md)从未完成的 PRD 出发，展示给需求、确认方案和验收结果。
[知识案例](docs/zh-CN/knowledge.md)演示过期指南、实现冲突和后续复核。
案例均为原创合成工程，不是生产背书。

## CLI：需要记录时再用

CLI 为长任务、交接和重复验证保存约定、输入与执行结果；不调用模型。
普通任务可以只用 Skill 和工程原生工具。需要记录时，Agent 准备技术字段并执行命令，你审阅重要边界。

当前是源码/本地包预览版，**尚未发布 npm 包**。可选 CLI 需要 macOS/Linux、Node.js 22.16+ 与 npm；
这不限制业务工程的技术栈，也不要求向业务仓库添加 npm 文件。安装方法见[接入指南](docs/zh-CN/installation.md)。

已有 CLI 时：

```sh
clinx status
clinx COMMAND --help
```

`status` 只汇总本地安装、配置和任务，不运行检查或自动选任务。
没有本地安装记录不表示宿主没有 Skill，缺少配置也不妨碍直接研发。
确需工作区内安装时，使用 `clinx init --agent codex --apply`；已有副本不重复初始化。
机器调用用 `--json`；预览不是强制的额外人工确认。

深入使用见[记录与续接案例](docs/zh-CN/recorded-delivery.md)、[CLI 参考](docs/zh-CN/cli.md)、
[工作区与归属](docs/zh-CN/workspace.md)。现有工程工具优先，不强制图谱、知识数据库或第二套部署平台。

## 质量与边界

方法和 Skill 不绑定企业、语言或场景。CLI 的执行和解析有明确支持范围：
本地通过不等于集成验证，发布就绪不等于发布授权，保存知识不等于知识正确。
命令继承当前权限、环境与网络；clinx 不是沙箱、Agent 运行时或环境构建器。

[验证指南](docs/zh-CN/validation.md)覆盖实现与发行检查；
[评测协议](docs/zh-CN/evaluation.md)单独衡量 Agent 效果，目前未证明普遍提效。
安全与敏感数据边界见[安全说明](SECURITY.zh-CN.md)。
