# 让工程知识真正用于下一次任务

[English](../en/knowledge.md)

交付软件变更时使用 `clinx-delivery`；独立调查工程、沉淀经验、整理知识或复核旧资料时，
使用 [clinx-knowledge](../../skills/clinx-knowledge/SKILL.md)。两者共用知识规则，均不依赖 CLI，
也不要求安装图谱引擎或新建知识库。

## 从工程和问题开始

完成[安装](installation.md)后，把以下请求交给 Agent：

> 使用 clinx-knowledge。工程：[本地目录或获准访问的仓库]。
> 调查这个系统如何导出数据、如何处理保留期限。复用已有文档，在现有维护位置修正有用的指南。
> 可以读源码并运行已有本地测试，不修改产品代码、政策、共享系统，不发布任何内容。
> 说明证据、冲突、未调查的边界，以及下一次任务如何找到结果。
> 只对无法自行查明的重要决定或权限问题询问。

已知工程从当前入口和本地绑定中取得，不必重复提供路径，见[上下文复用](project-context.md)。
新上下文只补缺少的工程或知识入口，复用已有协调目录。
Agent 只追踪本次问题涉及的链路，引用各源拥有的事实；
不应搬动仓库、在每个源里创建同样的文档，或要求你先准备代码地图。

| 请求                           | 意图            | 预期结果                           |
| ------------------------------ | --------------- | ---------------------------------- |
| 解释某领域的入口、规则和消费者 | Build / 建档    | 有源码依据、明确缺口的范围内导航   |
| 保存本次任务学到的内容         | Capture / 沉淀  | 归位到维护者的测试、操作方法或发现 |
| 整理这些重复指南               | Organize / 整理 | 保留冲突、统一维护入口             |
| 代码变化后复核文档             | Maintain / 维护 | 保留、修正、未决或已替代的结论     |

这些是可选择的意图，不是四道顺序审批。既有归属与评审规则仍然适用；
向共享知识发布或操作生产环境，需要对应授权。

## 走一遍原创案例

在已审阅的 clinx 源码目录执行：

```sh
node evals/knowledge/prepare.mjs
```

如果使用已安装的包，`clinx resources --json` 可定位 `skills.knowledge` 和指南；
准备脚本位于该包根目录下的 `evals/knowledge/prepare.mjs`。
脚本创建新的临时工程，返回 `workspace`、`request`、`retrievalRequest` 和评估文件路径，
不安装工具、不调用模型。

给新 Agent 工程路径、返回的请求和选定的 Skill；不要把评估文件和下面的解释放进其输入。
案例用一个小型 JavaScript 模块保证可复现，不要求实际项目采用这个语言或架构。

原始工程包含：

- README 中的正常入口，链接到操作指南；
- 同一入口还能找到重复过期指导的速查表；
- 旧指南声称 JSON 导出需要新增实现；
- 当前已有 CSV、JSON 实现与导出测试；
- 较新的有效政策要求最多保留七天，但代码返回十四天。

正确结果不是再写一个导出器，也不是修改政策迁就代码。Agent 应修正过期的能力描述，
区分保留期限的实现缺陷和预期规则，并在指南里保留未解决冲突。
已有导出测试通过，并不能证明保留期限合规。因为请求只授权知识工作，产品代码应保持不变。

按评估条件检查改动、受保护文件和真实观察，不用固定标题或措辞判断质量。

保存并审阅本轮结果后，准备下一个检查点：

```sh
node evals/knowledge/prepare.mjs --after /path/to/previous/evaluator.json
```

每次调用创建新工作区和请求，原样携带 Agent 实际留下的指南，不替它修正错误，也不修改前一轮工作区。
给新会话的输入只有新工作区、返回的 `request` 和选定的 Skill；评估文件与快照不得向被测 Agent 开放。
第二个检查点是只读检索：Agent 必须从正常入口找到答案，而不是依赖评估者提供答案路径。

按同样方式继续，依次经历仅行为变化、生产者不变但新增注册消费者、消费者源码不可用、
仅配置变化导致批处理有效期限改变，以及不能被当成当前指导的历史观察重新出现。
最终请求恢复源码并授权实现，此时使用 `clinx-delivery` 修复所有注册路径，保留已有导出行为并补充回归测试。
这样验证的是知识能否帮助后续交付，而不只是文档质量。合成案例只模拟保留期限数值，
不包含生产存储或真实计时清理。

准备过程不调用模型、不执行产品代码，也不判定通过；它会拒绝受保护输入变更以及不安全或超限的复制，
但文件分离不是操作系统沙箱。推进前停止写入，保留失败回复和工具轨迹。
检查点顺序、权限范围、限制与独立验收条件见[评估协议](../../evals/knowledge/README.md)。
一条连续轨迹不是八个独立样本，也不证明普遍提效。

## 把结果放在合适的位置

不必为了使用 Skill 新建 `knowledge/` 目录，优先复用现有维护位置：

| 发现                         | 合适位置                 |
| ---------------------------- | ------------------------ |
| 可复现失败                   | 回归测试                 |
| 重复机械操作                 | 已有工具或聚焦的操作指南 |
| 设计理由和已接受取舍         | 设计或决策记录           |
| 入口、规则所有者和消费者导航 | 小型系统地图             |
| 临时任务选择                 | 任务记录                 |

在现有正文或元数据中说明用途、适用范围、证据与复核条件。源内规则留在对应仓库或团队维护处，
工作区地图只链接跨源关系。只读源可保存注明条件的观察或修改建议，不能冒充已批准指南。

实现观察、预期规则、推断和有效决定是不同结论。发生冲突时先查明变化，
不自动优先相信代码或文档。历史批准不能授权新的操作。

来源新鲜度、证据支持程度、适用性与授权应分别判断。版本和哈希取自实际来源，不能由模型编造；
字节匹配也不能证明结论成立。涉及全部消费者的结论，还需检查相关注册与关系变化：
新增消费者可能使系统级结论失效，即使引用的生产者没有变化。复核受影响范围，保留仍然有效的发现，
并修正正常检索入口，而不只修改无人会读到的副本。

重要指导还应区分支持结论的证据与可能使其失效的复核范围。消费者文件没变能支持已知关系，
不能证明没有新增消费者。保留未改动的指导不等于重新确认。准备提升为可复用指导前，
复核关键来源、目标及维护者正文是否发生变化；可用时复用带版本条件的写入或原有评审。
二次检查不是跨来源事务。无法建立新鲜度时，保留注明条件的观察，只暂停依赖它的提升动作。

在授权范围内修正受影响的链接、速查表与生成摘要，报告无法更新的派生副本。
保留历史证据，但没有当前支持时，不在后续总结中恢复已失效的指导。
可重建摘录和获授权快照可以保留，只需明确来源，不能成为另一份独立维护的权威知识。
这些做法不要求新增 Claim 数据库或知识 CLI。

## 按问题使用代码智能

先用可用的搜索、源码读取和语言工具。对于存在共享消费者的重要改动，已有且已核验、增量
成本低的关系工具绑定必须参与影响检查；没有可用绑定时，必须用原生搜索和源码导航生成等价
候选清单。消费者多、多跳影响或边界难追踪时增加关系查询；陌生术语可借助语义解释。
小型局部改动不要求临时建立索引。

内置[使用约定](../../skills/clinx-knowledge/references/code-intelligence.md)
说明原生搜索/LSP、需经当前源码核验的图谱候选 codebase-memory-mcp，以及用于流程分析的可选
GitNexus 专用后端的使用边界。它不是对所有版本认证过的安装指南。clinx 不安装或配置这些工具。

对选定版本核实实际根目录/worktree、索引输入、更新结果、查询限制及覆盖缺口，
读取其帮助与工程绑定。无法确认新鲜度时，在授权内刷新或直接查看当前源码。
保留不确定原因：失败、过期、不支持、歧义或截断。查不到边不代表没有消费者。

重要关系回到当前源码、真实协议和消费者行为核验。图谱字段检查不能替代嵌套结构、类型、
可空性、单位与兼容性测试。运行观察只覆盖实际环境和负载，不代表所有可能路径。
通常使用一个主要关系后端即可；有重要分歧时用独立手段核验，不对相关索引进行多数投票。

## CLI 做什么、不做什么

`clinx init` 安装两份 Skill；`clinx skill status/update/remove` 一起管理其文件。
任一完整 Skill 目录也能独立使用。`clinx resources` 定位内置资源。
现有任务、上下文和证据命令仍按需用于交付续接；纯知识请求不必制造一个交付任务。

当前没有 `clinx knowledge` 命令、图谱 Provider Registry、自动正确性评分或语义新鲜度裁决。
来源核实和检索验证由 Agent 执行。[评估指南](evaluation.md)区分机械测试与 Agent 效果；
生成文档或一次小型演练都不能证明普遍提效。
