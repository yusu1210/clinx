# 评测：实现正确与 Agent 有效是两个问题

[English](../en/evaluation.md)

本篇区分两个问题：实现是否符合文档，以及方法或 Skill 是否改善 Agent 交付结果。
仓库已有较完整的确定性实现测试和一次小规模协议试点，但受控样本仍不足以证明质量、
速度或成本普遍改善。

维护者可以按下文复现检查、运行受控对比并如实报告结果，不能把夹具运行成功写成产品收益。

## 2026-09-13 批量重置试点

三个独立 Agent 分别收到同一原始工程与需求的隔离副本，对应基线、仅 Skill、Skill 加可选 CLI。
三组都通过隐藏验收器的 16 项接收语义与故障检查，并如实说明了集成边界。
可使用 CLI 的 Agent 没有生成 clinx 任务或证据记录。脱敏结果保存在
[`evals/results/2026-09-13-bulk-reset-pilot.json`](../../evals/results/2026-09-13-bulk-reset-pilot.json)。
由于每组只有一次，且该 PRD 已详细给出
失败语义，结果不能估计相对效果。它证明了夹具、处理材料隔离和隐藏评分链路可以端到端运行，
也说明 CLI 价值应在连续性或证据负担较重的任务中验证，不能仅因可用就假设有效。

确定性测试回答 CLI 是否遵守声明语义；受控行为试验回答方法与 Skill 是否改善真实结果，
且收益足以覆盖交互与维护成本。第一类通过不等于第二类成立。
合成示例证明可运行边界，不代表企业生产资格或已覆盖真实业务全部要求。

## 可复现实现检查

- `npm run check`：格式、类型、构建、单元/集成回归与文件卫生。
- `npm run test:coverage`：只以编译后 CLI 模块和入口作为实现覆盖率分母，不统计 Skill 效果。
- `npm run test:maven`：真实双模块 JDK/Maven、指定用例及拒绝旧报告的空操作反例。
- `npm run test:package`：本地包、独立安装、命令、示例、评测准备与 Skill 接入。
- `npm run test:example:http`：真实 HTTP、服务端角色、非法输入、写失败与重启持久化，不操作浏览器。

回归包括错误谓词、零/错/跳过用例、格式矛盾、陈旧输出、跨源和方案变化、执行中断、
初始化冲突、任务修订、授权声明不能批准外部条件等。
CI 文件存在不代表已经在托管环境运行。

常规测试还检查评测准备安全、搬迁后的 CLI 运行时、已提交的越界修改、确认审查绑定、
漂移归属、评分超时与缺失结果统计；这些确定性测试不调用模型。

## 同等输入的行为试验

错误知识安全、新会话检索和连续变化后的复核，使用[知识练习](../../evals/knowledge/README.md)。
它覆盖沉淀、检索、行为变化、新增消费者、来源不可用、仅配置变化、历史证据重新出现和后续实现，
提供原始输入与评审条件，不自动判断语义正确。已失效结论在后续检查点持续复核；
未做语义评审保持未知，不算通过。准备命令在隔离副本间推进，保留实际指南与评估方快照；
这些是同一场景的相关检查点，不是独立样本。知识收益与代码智能收益应分开测试；
图谱对照组仍保留原生搜索和语言工具。知识练习成功不代表已证明交付收益。

固定宿主/模型、输入版本、工具与权限，每次使用隔离工作区。
分别测试无 clinx、仅 Skill、Skill + CLI；随机顺序、重复采样并保留失败，不只挑最好轨迹。
[场景目录](../../evals/scenarios.json)包含 14 个场景。对于跨仓库所有权、漂移后恢复和确认边界研究，使用
[Agent 基准套件](../../evals/benchmark/README.md)，其中包含隔离夹具、隐藏验收控制和阶段转换流程；
仅在获得授权的评测环境中运行。

```sh
node evals/prepare.mjs greenfield
node evals/prepare.mjs brownfield
node evals/prepare.mjs cold-start baseline
node evals/prepare.mjs cold-start skill
node evals/prepare.mjs cold-start skill-cli
node evals/prepare.mjs bulk-reset skill
```

每次创建隔离工程、request.md 和含哈希的 initial-inputs.json。
greenfield 是空工程；brownfield 只有原始未扩展代码、测试与中性说明，
不带 clinx 配置或解题约定。cold-start 只有 PRD 与 service/viewer 两个工程。
三组原始产品输入哈希一致，只有方法处理不同；准备命令不启动 Agent、不执行项目、不安装依赖。

baseline 不复制 Skill；skill（默认）复制 Skill；skill-cli 额外提供 CLI。
是否实际使用 CLI 需要在 run-record.json 中单独记录。
CLI 运行时与答案、评估器分离，逐个解析并链接实际安装的直接运行依赖，按协议只读使用，并在输入记录中说明；
这不是沙箱，也不是依赖字节认证。只能给候选 Agent 原始输入和选定方法，不给完整 clinx 答案库。

## 独立验收与反例

完成并冻结 cold-start 候选结果后，由评估方运行：

```sh
node evals/grade-cold-start.mjs /path/to/prepared/project
```

cold-start 通过真实回环 HTTP 检查 16 个时间窗口/可见性用例，包括伪造请求时钟、
亚毫秒边界、缺少时区和不存在的日期。
原始测试通过但新需求验收失败；兼容实现通过，排除起始边界、精度丢失、时区和日期规范化的反例失败。
它不检查浏览器渲染、范围忠实或提效；还需运行原测试、审查差异和实际界面。

完成并冻结 bulk-reset 候选结果后，运行：

```sh
node evals/grade-bulk-reset.mjs /path/to/prepared/project
```

bulk-reset 使用原始偏好应用、网关及已有分批/重试能力，
通过评估方持有的真实本地接收端检查 16 个用例：重置回读、无关状态、身份、去重、容量、
非法输入、重放、永久/暂时失败、结果未知与部分成功恢复。
两个兼容分区方案通过，八个错误对照被拒绝；检查效果与调用限制，不规定辅助函数名或代码相似度。
不测生产延迟和远端容量。

这些反例验证评估器，不能证明独立 Agent 遵循 Skill。
保持评估器和参考实现不进入候选输入；结果冻结前隐藏验收答案。
评估会导入并执行候选代码，继承调用者权限；先审阅，在获授权环境运行，
并使用外层进程超时。HTTP/异步等待有期限，但进程内超时阻止不了同步阻塞或卡住的模块导入。
不得为让试验通过而扩大网络、部署或委派权限。

## 测量真实效果

记录每次语义正确性、复用/归属、范围忠实、错误完成、恢复、实际成本与交接质量。
披露分母、失败和未知；未知成本为 null，不是零。
保持既有平台工具与领域 Skill 一致，不能把它们的收益算成 clinx 的收益。
记录模型/工具版本、输入哈希、允许目标、日期、人工时间、总耗时、平台等待、
调用成本、重试、验收失败和返工。区分首次接入与后续复用，考虑方差。
省掉必要消费者验证所得的“更快”不算改进。

### 区分修复效果与首次执行效果

在独立验收反馈前冻结第一次完整提交。授权尝试内的原生测试、探针和修复属于首轮交付；
禁止它们会惩罚早期反馈。若内部审查属于方法，各组应一致地允许并计入成本。作者审查前首稿
可另存快照，但不能替代完整方法的评价。预先规定提交边界与预算，保留超时和未完成提交。
分开报告该快照与反馈后结果，计入全部调查、审查和修复成本；验收反馈不抹去失败或产生新试验。

判断遗漏可预防时，说明决策当时可访问的证据、在范围和预算内可行的发现/核对路径，以及它会
改变的决定。文件存在本身不证明可预防。从可观察记录区分检索、理解、动作和反馈失败；打开文件
不证明理解，无充分依据时归因保持未知。需执行才可发现、环境暴露与可预防性可以重叠，
不能把它们当作互斥的严重程度分类。

研究恢复时，区分最早有外部依据的错误动作、Agent 首次可获得的相关反馈、识别错误和已验证的修复。
记录期间新增的工作与影响，以及信号由谁提供；最终通过不证明自我发现，也不撤销先前效果。
按当时可获得的证据判断，不用隐藏的未来需求倒推。歧义或渐进累积的失败保持未定，
不要强行给每条轨迹标注唯一首错。从匹配的起点比较反馈变化；事后定位本身不证明
在线审查者当时能够发现错误或改善交付。

评分前，先让审查者对齐约定的交付终点。仅交付方案的任务可以明确外部决定和运行检查，
并据此暂停依赖它们的实现或发布；诚实披露这些缺口本身不是新增方案缺陷。
遗漏可达的效果、规则矛盾或无依据的就绪声明才是缺陷。发现应提供前提、来源、反例、
后果和受影响终点；分歧需要核实，不能把严重性标签当成证据。保留原报告，单独记录
复核裁决。连续无新增发现只支持实际检查范围，不能证明完整性或独立任务多样性。

冻结完整处理条件，包括引用的 Skill 文件、提示和可用工具，而不只是 Skill 入口；
每个版本保留文件清单。采集含过期链接时，除哈希外还要比较输入内容；
去掉 URL 后文本一致，不证明链接页面或图片内容一致。

区分“方法指令”与“原生运行时”两类处理。方法指令对比固定宿主、模型和执行工具，
只改变方法文件；工具可用性对比固定方法，只改变某个可选本地工具是否存在；
原生编排器对比则包含产品自己的模型选择、调度、安装和外部集成，应作为整套系统处理，
不能与方法指令结果合并。如果原生运行时需要新增全局安装、身份、网络服务或共享效果，
应保留这些接入成本或不可用状态。手工遵循其导出指令可以检验方法，
但不能作为原生运行时已执行的证据。

计时前由评估方根据相同锁文件和已审阅字节准备候选依赖。
使用评估方控制的不可变副本或隔离缓存，避免并发准备以不同方式污染共享缓存。
预先规定准备失败时的对称降级路径。注册表、缓存和宿主故障属于运行观察，
不属于候选正确性失败。评估方之后可以恢复一套公共环境并执行所有已冻结提交，
但这不会改变候选当时可观察的条件，也不能覆盖原耗时和原声明。

修订方案或聚焦复核衡量的是已暴露案例上的恢复，不是新版 Skill 的首次成功率。
与完整的新会话执行分开统计，并将原调查、评审和修复计入总成本。
用于调优的案例保留为回归，泛化结论使用未参与调优的任务；同一 PRD 的重复会话
不构成独立的任务多样性。评测者已经知道答案时，即使另开会话也须披露这一暴露。

当 clinx 与图谱都可能解释结果时，采用配对的 2×2 对照：原生、原生加图谱、
clinx、clinx 加图谱；所有组都保留原生工具。随后只在相关因素针对已观察失败时，
比较完整与精简 Skill，或仅 Skill 与可选 CLI。预先声明验收标准、成本指标、
不可接受的退化和停止条件；报告不确定性，不凭一次成功选出优胜者。

### 衡量不同任务之间的学习效果

要检验保留知识是否减少重复调查，应预先确定同一演进系统上的一组不同需求。选用未参与
指引调优的领域，使用全新会话，各组起始源码、工具、权限和验收相同。比较原生辅助、冻结的
最小指引与当前 Skill，保存两种指引的全文及清单。这是研究协议，不是已完成评测或日常交付要求。

每组将实际产生的代码、测试、工具和合法工程指南带到下一任务。原生 Agent 也必须可以保留
正常产物；删除其文档会混淆效果。不把会话、评估方答案或隐藏的未来需求传入候选上下文。
内部审查与修复预算保持对称。失败任务保留在分母：预先规定停止序列还是计入修复后继续，
不能静默替换为参考补丁。

根据领域纳入复用、契约变更、新消费者、过期指南与恢复。逐步验证外部可观察需求、旧行为、
权限和恢复。后续需求挑战前序设计选择，但不强制某种内部架构。通过源码评审跟踪改动放大和
规则重复，不采用通用复杂度阈值。

在同一任务序列上比较各组累计成本与质量。后续任务可能更难，所以单任务成本单调下降既不是
必要条件，也不是学习效果证明。以整个序列为相互依赖的实验单位，五个检查点不等于五个独立
样本。跨未见任务领域重复，保留失败和不确定性。设置、来源复核、知识维护、审查、返工与
人工注意力都计入总成本。再次调查仍有效的事实，只有扣除其后果或变化所要求的必要复核后，
才能判断是否属于浪费。

若要把增益归于保留资产，应从同一冻结源码检查点分叉，保持方法/工具相同，只改变选定资产的
可用性，并加入过期资产条件。同时改变指令与资产只能衡量组合处理。若每轮都将各组重置到统一
参考实现，应预先规定保留内容并检查兼容性：地图、测试和工具可能引用已被丢弃的代码。
适配与复核计入成本；不得静默修复资产、借工具带回候选补丁或通过参考实现泄露未来需求。
这衡量向参考实现迁移的效果，不是各组自然维护轨迹，与延续各自代码的实验分开。
仅在研究边际价值时加入图谱/CLI因素。已有知识和上下文练习保护已知失败，不证明未见序列收益。

比较基线应服务于实际决策。在已有团队采用 clinx，应比较未来工作及新增接入成本与团队当前的
经验和工具；不能只向人类基线追加全部历史学习成本。研究新成员入职是另一种比较，需要对齐
项目历史和责任方的访问条件。两类比较都不能为了少搜索而牺牲必需的正确性或权限约束。

通过保留资产的下一次适用使用来评价它，计入发现、来源复核、维护以及错误或过时指导造成的损失。
少读文件或少问问题，既可能是有效复用，也可能是未经核对的假设；需要说明改善了哪个决策。
新测试也可能固化错误规则，因此仍需规则依据和独立的行为反例。重复需求能由既有责任位置或
可执行检查满足时优先复用；文档、索引或环境投入不能仅凭长期存在证明价值。
区分有依据的复用、必要复核、可避免的重建和不安全复用，并保留未知归因和未使用的观察。
研究学习是否预防复发时，以后续真正适用的机会为分母，而非全部任务；没有适用机会时未复发
不证明预防有效。把成功归于资产前，记录它实际起到的作用或比较其有无条件。

### 采集不等于交付效果

[上下文场景](../../evals/context/README.md)准备七种不提供工程路径的请求，覆盖已知、迁移、错误、
歧义或不可用的工程及只读依赖。新会话的选择和源码使用，应与素材完整性分开验收；
准备脚本不运行 Agent，也不证明效果。

分别评估首次接入、同工程第二个任务、多工程、小修复、新会话续接和工具/权限不可用的场景。
把必须由人操作的次数，与 Agent 调用、重复调查、维护文档和重跑次数分开记录；
把表单从用户转给 Agent 并不自动减少总成本。检查是否真正跳过无用接入、
是否仅复用仍适用的事实，以及少调用后独立验收是否仍成立。
不能仅凭指令变短或确定性 CLI 测试通过就声称已测得提效。

Skill 调用次数、用户反应、AI 代码占比和阶段/门禁进度，可以帮助定位采用情况和摩擦，
但都不是独立的交付质量或效率指标。不要为了计数把每份指南和规则都变成 Skill。
下一条好评可能属于别的任务；用真实任务/运行标识关联，无法确定的归因保持未知。

披露来源覆盖、采集失败和缺失时段。局部空样本不证明没有使用或没有失败。
区分观察到的零、未采集、不可用和部分覆盖，不从期望阶段状态或模型分数反推缺失观察。
在授权范围内保留原始依据，派生值说明计算基础；补齐采集不等于修复交付结果。

先复用已有合规测量。新增可选采集或导出前，明确授权、目标、最小字段、访问与保留期限，
不因采用 Skill 就自动安装 Hook 或上传提示词、源码和原始轨迹。
采集失败可以显式保留测量缺口而不阻塞研发；必需验收失败则应暂停依赖它的结论或动作，
不能用采集兜底值补成通过。

## 决定保留、简化还是移除

新增可选 Skill、包装层、检查或评审机制前，在已有问题或决策记录中说明：
它解决哪类具体失败或重复成本、预期改善什么、什么结果支持简化或移除。
不新增组件注册表或通用评分。

选择有代表性的新建、复用和混合能力任务，在原始输入、工具、授权相同的条件下，
比较有该机制、无该机制或简化版本，尽量一次改变一个因素。
同时计入首次接入、后续复用与维护成本，不能只看一次成功交付。
尚无效果证据的新机制仍是假设，不是已证实的改进。

| 决策 | 需要寻找的证据                                                   |
| ---- | ---------------------------------------------------------------- |
| 保留 | 正确性、恢复或效率的相关收益足以覆盖成本                         |
| 简化 | 更短的指令、已有工具或聚焦的检查仍能保留有效结果                 |
| 移除 | 原失败已不再适用，或同等授权条件下的对照支持移除且不损失必要行为 |

模型/宿主、工具能力、工程契约或任务形态变化，以及机制反复制造开销或未能阻止目标错误时，
重新对照新的基线；既不假设模型更新后必然应删除，也不认为组件越多越成熟。
调整时保留依据并修正受影响的指引，便于后续退化时定位。

低频但严重的失败需要针对性反例，不能只看平均任务分数。
保护机制启用期间没有出错，不代表它没有价值。未经责任方授权，不能把移除强制权限、
审批或项目义务当成试验组；必要时用隔离模拟。收益未知时做聚焦调查，不自动删除或扩张。

## 确认边界试验

协作场景复用 bulk-reset 原始材料。只给请求与方法，在实际用户确认前冻结文件和工具轨迹，
再以真实用户消息继续。检查等待期间未实现、批准后范围内继续、技术确认不等于发布授权、
拒绝/含糊/缺失确认、已授权自主不发明额外关卡。不要使用真实生产目标或假凭据。

这些是试验协议，不是已完成多轮试验。现有自动化只证明字段保留约定、
引用文件变化使绑定失效、人工 pass 不批准外部条件；不证明 Agent 行为或企业强制审批。

## 当前测量边界

本项目尚无已完成、重复的 baseline-versus-Skill 受控研究。
自评不是独立试验，也不能把某个指令版本上的结果转移给另一版本。
声称普遍提效前，按同条件在有授权的代表性任务上实际测量，只公开脱敏且可复现的证据。
