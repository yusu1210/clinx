# CLI 命令与结果语义

[English](../en/cli.md)

先[安装 CLI](installation.md)。`clinx --help` 列命令，`clinx task add --help`
或 `clinx help task add` 查看该命令的输入与示例。默认输出可读文本，在终端和管道中保持一致；
机器消费显式加 `--json`，帮助与版本也支持。错误写 stderr；JSON 错误含 `error`、`code`、
`hint`，Schema 错误另含字段级 `issues`。未知、用错位置或显式空白的选项值报错；
需要默认行为时省略该选项。不交互提问，不使用 ANSI 颜色或遥测。
`--root` 选择已有目录，默认是调用 cwd，不向父目录自动查找。

| 命令                                                            | 作用                                                 |
| --------------------------------------------------------------- | ---------------------------------------------------- |
| `resources`                                                     | 定位安装包内 Skill、模板、Schema、指南与案例，只读   |
| `status [ID]`                                                   | 汇总本地接入与任务；仅对明确任务检查续接状态，不执行 |
| `example list`                                                  | 列出公开案例与工具前提                               |
| `example copy NAME --to DIRECTORY`                              | 只向新目录复制案例，不执行或安装依赖                 |
| `inspect`                                                       | 有界只读候选，不初始化、不执行                       |
| `init [--agent generic\|codex]`                                 | 预览 Skill、许可与入口                               |
| `init ... --apply`                                              | 安装 Skill、许可与入口，记录文件归属；冲突停止       |
| `skill status`                                                  | 对照记录、本地与内置 Skill，不查注册表或宿主         |
| `skill update [--apply]`                                        | 预览/更新受管文件，保留用户文件并备份替换内容        |
| `skill remove [--apply]`                                        | 预览/移除未改动受管文件并备份，不删任务与非受管文件  |
| `task add --file PATH`                                          | 验证并保存显式任务约定                               |
| `task list [--limit N --after NAME]`                            | 分页列出精简任务摘要，不自动选任务                   |
| `task show ID [--limit N --after NAME]`                         | 无需配置，读取已存约定、最近交接与一页修订历史       |
| `task revise ID --file PATH --reason TEXT`                      | 保留旧约定，应用完整替换                             |
| `task checkpoint ID --file PATH`                                | 追加输入绑定的续接说明                               |
| `evidence attach ID --file PATH`                                | 复制已审阅的本地观察附件，不批准验收                 |
| `evidence list ID [--record UUID]`                              | 检查附件字节及本地变化，不查询远端                   |
| `context ID [--focus discover\|contract\|build\|verify\|learn]` | 返回约定、最近检查点、变化和相关索引                 |
| `validate [ID]`                                                 | 验证配置、源根及可选任务引用，不运行项目命令         |
| `verify ID [--claim NAME]`                                      | 预览所需检查与外部条件                               |
| `verify ID --run [--allow-external]`                            | 执行已审阅、已获授权的命令，保存本地记录             |
| `reconcile ID --receipt PATH [--claim NAME]`                    | 对当前输入重核旧记录，不重新执行                     |

`--file` 相对调用 shell 的 cwd，可从项目外导入；`--file -` 读取完整管道 JSON，上限 8 MiB，
拒绝交互式终端输入。`--to` 也相对调用 cwd，父目录须已存在；执行记录路径相对 `--root`。
源根可使用绝对路径或相对 `--root` 的路径，包括显式兄弟工程；检查 cwd 限于该源，报告路径限于检查 cwd。
不展开模板、glob 或 shell 插值。
配置中的检查 argv 原样保留空字符串和空白参数，程序名必须非空白。argv 含 1–128 个字符串，
每项最多 16,384 字符，禁止 NUL。
检查 ID 忽略大小写后仍须唯一，以适配区分和不区分大小写的文件系统；执行前即验证此约束。

启动诊断通过允许列表中的 `causeCode` 保留原因，不暴露路径或堆栈。
`EMFILE`/`ENFILE` 报 `RESOURCE_LIMIT`；包模块不可用仍报 `INSTALLATION_INCOMPLETE`。
命令执行中的意外异常报 `CLI_FAILED`，不误判为安装问题。CLI 不承诺在某个特定操作系统
文件句柄上限下启动；应用遍历的资源边界与运行时加载器分开验证。

## 输入与初始化

`resources --json` 返回 `skills.delivery` 与 `skills.knowledge` 路径。
初始化与受管更新/移除覆盖两份 Skill；任一完整目录均可独立使用。

init 不生成配置、地图、指南或任务；按需使用[模板](../../templates/workspace)和 Skill。
缺少配置不应阻碍普通研发。初始化不覆盖现有文件；Skill 更新按记录基线替换受管文件，
归属、冲突与备份见[安装与恢复](installation.md)。

每个 source 必须明确非空 `inputs` 字面路径；`exclude` 排除指定子树。
直接指定的输入若本身被排除则报错。目录名与 gitignore 不自动排除任何输入。
选择宽范围时明确排除生成物与私密记录，保留相关源码、锁文件与配置。
符号链接输入拒绝；作为命令的可执行符号链接保留原调用身份。
作用范围检查不推断遗漏输入。每源最多 50,000 条目（含目录）、128 MiB，每文件 8 MiB。

`--root` 选择工作区协调目录，不要求是 Git 仓库。任务 `sources` 是可选的非空相关源 ID 列表；
省略时绑定所有配置源。包含未修改的依赖和受影响消费者，不能只填改动源。
检查源和任务的源文件引用必须在此范围内。`validate ID` 检查任务相关根；不带 ID 则检查全部配置根。

任务选择来源 ID，不支持每任务覆盖 `inputs`。选择同一来源的任务共用其配置选择器：即使任务
行为未受影响，宽泛 `src` 内其他位置的改动也可能要求重核。两个来源 ID 不能别名到同一真实根。
这是保守绑定，不推断语义影响；先检查改动，再决定复核范围。只有覆盖共享依赖和消费者后才收窄
输入，不能只为恢复摘要匹配；修改选择器也改变绑定。遗漏依赖时，行为可能变化而声明输入仍匹配。

配置和任务 `context` 都支持 `{ "source": "service", "path": "docs/design.md" }`。
省略 `source` 表示工作区本地文件；任务引用的字节参与约定绑定，配置上下文仅用于导航。
路径限制在选定根内，不经过符号链接。
`context ID` 按焦点筛选导航，源拥有的条目还按任务源范围筛选，工作区条目仍可入选。
这是相关性选择，不是权限控制。工作区本地引用相对 `--root`，不是相对任务目录。
文档归属与输入、产出分离见[工作区布局](workspace.md)。

`definitionDigest` 绑定任务源选择器与所选检查的执行定义。
回执的 `definition` 同时保存源选择器和检查；先独立于当前配置核对保存摘要与内部引用，
再解释历史观察。保存定义损坏时，解释保持未知。
仅导航变化、无关检查或源变化、产品版本及读取者运行环境不使限定范围的回执失效。
若配置文件显式属于源输入，仍绑定其完整内容。检查点和附件绑定任务引用的全部检查。
记录格式、证据 `protocolVersion` 和产品版本分开，不支持的协议保持未知。
`current` 只描述声明的本地绑定，不表示所有工具链或远端状态都没变；
环境要求需由真实项目检查或平台证据验证，不能用读取者环境替代。

相关绑定变化可能使整份记录陈旧；`reconcile` 不合并多次执行，也不推断检查依赖。
可以保留未受影响的代码，但需重新运行所选声明才能取得当前 CLI 支持。
详见[输入绑定与恢复](architecture.md#输入绑定与恢复)。

空仓库可立即使用 Skill。CLI 指纹需要真实文件：确需记录时可保留实际需求或方案，
代码出现后再声明相应输入；也可以先用普通交接。不为满足 Schema 创建占位源码、
虚构检查或把生成的执行记录作为输入。

## 无需初始化的本地状态

`clinx status` 汇总 CLI 版本、受管 Skill、可选配置和一页任务摘要，不对源内容计算指纹，
也不按最近时间猜测当前任务。`clinx status ID` 只读取指定任务并比较已存输入绑定，
不读取其他任务历史；分页选项仅用于不指定 ID 的情况。
缺失或损坏的组件尽可能独立报告。退出零表示返回快照，仍应查看 `issues` 及各任务的问题；
配置有效不等于源可访问或工程就绪。
配置 Schema 问题在 `issues[].fields` 中保留字段路径和原因，文本与 JSON 均可定位，
不回显输入文档内容。
文本输出列出 Skill 缺失、修改及与包不一致的文件。任务摘要显示已存交接状态；
指定任务后还显示摘要与阻塞原因。这些是需要复核的历史说明，不是当前批准，
也不证明当时的阻碍仍然存在。

不运行初始化、安装、工程命令、审批检查或远端查询。未由 CLI 管理的 Skill 可能已经由
宿主或团队提供，`hostDiscovery` 始终是 `not-observed`；即使输入一致，`acceptance`
仍是 `not-assessed`。按需用于排障或续接，不要求每次任务前执行。

## 静态调查

无配置时，`locations` 最多列出 32 个直接子目录线索，最多访问 256 个目录条目；
导航提示略过点目录和常见生成目录，不跟随符号链接、不读取子目录内容。
提示不是声明源，也不决定证据排除范围；`locationsTruncated` 标明枚举不完整。
需要调查相关子目录时再显式选择其路径。

`inspect` 在没有配置时读取选定根目录，有配置时读取显式源。
返回文档/清单路径与哈希、命令候选、来源、审阅说明和解析/访问诊断。
不读 `.env`，不导入脚本、不执行、不扫描父工作区、不展开 monorepo glob、
不探测网络、不安装工具、不写配置。

支持根目录的 npm/pnpm/yarn/bun 脚本约定、Maven compile/test/verify（优先已有 mvnw）
和显式检查。包管理器声明或单一锁文件族作为依据；都缺失时把 npm 标为约定而非事实。
冲突或未知管理器不猜命令。嵌套工程显式指定根或源；其他工具链人工读取原指南。

候选的 `readiness` 是 `not-checked`，`sideEffects` 是 `unreviewed`。
脚本名称、包装器存在不证明权限或可用性；执行前读实际定义、钩子和目标。
每份文件最多 256 KiB，每清单最多 256 个脚本，拒绝符号链接。
缺少可选文件正常，其他访问/解析问题列为诊断。已声明检查的目录不可用或不安全时，
报告该检查的问题并保留其他候选；无效 clinx 配置或不可用的源根仍是命令错误。
退出零仅表示调查完成，不表示工程有效或就绪。

## 模型与结果

[配置](../../schemas/config.schema.json)、[任务](../../schemas/task.schema.json)、
[检查点输入](../../schemas/checkpoint-input.schema.json)、[检查点记录](../../schemas/checkpoint.schema.json)、
[执行记录](../../schemas/receipt.schema.json)、[附件输入](../../schemas/evidence-input.schema.json)
与[附件记录](../../schemas/evidence.schema.json)由实现模型生成。
还需 CLI 核对交叉引用和路径约束。

只需续接的任务可同时省略 `defaultClaim`、`claims` 和 `obligations`，在已审阅的来源输入上使用
`task add`、`task revise`、`task checkpoint` 和 `context`，无需编造验收声明。验证时必须提供三者
构成的完整计划；缺项或空计划会被拒绝。需要时通过 `task revise` 添加，绑定变化后重新核对旧说明。
已有声明约定的结构与绑定语义保持兼容。

`claims` 是任务自行命名的验收声明，不是内置质量等级。每项至少有一个验收条件；
每个条件引用一组全部必须满足的检查，或一个外部条件。计划中的 `defaultClaim` 必须指向已声明的声明。
同一检查支持多个条件时，实际断言必须覆盖它们，CLI 不判断语义映射是否充分。

方法不要求 JUnit 或任何测试框架。CLI 目前只解释退出状态和严格子集的 JUnit XML；
跨语言执行不等于支持所有原生报告格式。

`{ "format": "exit-code" }` 适用于退出状态能表达实际断言的已审阅命令，
例如编译器、Schema 校验或原生测试。它保存 stdout/stderr，但不解析用例数、跳过状态、
原生 JSON/TAP 或设备结果。需通过原工具确认选择与失败语义：任务已受理、零用例、
报告导出成功都可能退出零。重复出现的实际缺口可补项目自己的聚焦断言，不强制更换框架。

JUnit XML 是可选报告适配，不要求 Java。已有工具能产生支持的报告、且需要具名用例时可用：

```json
{
  "format": "junit",
  "from": "files",
  "paths": ["target/surefire-reports/TEST-example.PolicyTest.xml"],
  "minTests": 1,
  "expectedTests": ["example.PolicyTest#rejectsUnavailable"]
}
```

`from: "stdout"` 要求纯 XML stdout，不允许 paths。
`minTests` 默认 1，`expectedTests` 默认空；重要检查应指定实际用例身份。
用例 ID 为 `classname#name`，没有 classname 时回退套件名。
失败用例使检查失败；跳过、缺少预期用例、格式不支持或报告缺失/陈旧使结果不确定。
DTD/实体、重复身份、计数矛盾和未支持的套件级失败/跳过不能通过。
非零退出表示失败；无法启动、超时、中断或执行未知表示不确定。
默认超时 120 秒，可配置 50 毫秒到 1 小时。长期服务应由宿主管理，检查应能结束。

支持递归的 `testsuite`/`testsuites` 和 Node 的直接 testcase；未知结构子元素（含未支持的
重跑扩展）不忽略，结果保持不确定。支持 `properties`/`property` 及纯文本的
`system-out`/`system-err` 元数据。原始 XML 保留，记录中的 `summary` 仅含
`total`、`passed`、`failed`、`skipped`；核验重新解析完整报告，不只相信计数。

浏览器、设备或 Trace 的原始产物保留在原工具处，由宿主工具检查。
[附件](evidence.md)可复制限额内的已审阅普通文件导出，不能直接导入目录结果包或批准验收。
没有解析器不阻止正常研发，把文字声明伪造成通过的 JUnit 也不算验证。

## 退出码

| 值  | 含义                                                       |
| --- | ---------------------------------------------------------- |
| 0   | 结构有效、成功的本地操作或预览；验证时表示所选声明获得支持 |
| 1   | 当前适用的必要观察至少有一项失败                           |
| 2   | 外部条件未决、证据缺失或当前适用性不足                     |
| 3   | 输入、路径、存储/锁或其他操作错误                          |

必须读结果类型。预览的零退出不是验收；外部条件始终未决，没有人工强制通过开关。
附件列表退出零也不代表每条完整、当前有效或获批准。附件不改变 verify 的结论。
`--allow-external` 需同时有 `--run`，只是额外执行开关，不替代真实授权或平台审批。

## 恢复

`verdict.checks` 提供每项执行状态、重新解释的观察、原因及相对项目的日志路径。
缺少执行显示 `not-recorded`；陈旧记录中的历史 pass 不支持当前条件。
必须把观察、适用性和验收声明结论一起解释。

原始输出在 `.clinx/runs/UUID/`，不上传、不自动脱敏。
保存证据失败时保留已知执行事实与可用制品，但观察保持不确定。
无法建立执行事实的意外错误标为 `unknown`，不表示没有执行。重试写操作前先检查实际效果。
记录未写完时，部分日志不是已验证结果。SIGINT/SIGTERM 取消当前子进程组；
SIGKILL、系统崩溃或恶意进程脱离会话不保证完整清理。

新文件完整写入后才以排他最终文件名发布。崩溃可能留下未选取的 `.clinx-write-UUID.tmp`；
不能把它改名为正式回执或据此推断成功，应保留未知结果供诊断。
写入与读取采用相同的每文件 8 MiB 限额；多文件运行不是事务。

`.clinx/write.lock` 保存 PID 与时间。崩溃后确认该进程身份及没有其他写者，
才能手动移除那一个锁；不自动抢锁，PID 存在不证明身份。不同工作区根不是共享锁域。

`context` 返回 `no-checkpoint`、`inputs-match` 或 `reconcile-required`，
不重放、不选任务、不检查远端或进程存活。修订要提供完整约定和原因。
旧检查已移除或旧方案路径已迁移，不阻止有效的新约定替换；新约定仍须引用当前检查
和可读、未越界的文件，旧约定损坏或身份不符仍会拒绝。保留原 JSON，不重建旧引用字节；
具体见[修订绑定](architecture.md#输入绑定与恢复)。CLI 不回滚代码。
任务 ID 匹配 `^[a-zA-Z0-9][a-zA-Z0-9._-]{0,95}$`，标识
`clinx/tasks/<id>/contract.json`。标题可以使用用户的语言，不是唯一键。
`task add` 拒绝已有约定，`task revise` 不允许更改 ID。
仅修改标题也会改变任务摘要，使此前匹配的交接和证据绑定发生变化。
推荐风格与可移植性限制见[任务命名](workspace.md#为检索与续接命名任务)，不要求迁移已有合法 ID。

`task list` 返回 `{tasks, nextAfter}`，包含标题、模式、检查点序号/时间、焦点/状态和问题，
不展开完整交接，也不核验当前检查适用性；列出的任务可能需要修订后
才能验证、执行或采集新记录。
查看每项 `issues`：损坏任务目录和符号链接单独报告，不隐藏健康任务；普通杂项文件不视为任务。
列表退出零只表示枚举成功，不表示每条记录有效。
只有任务文档的目录也可能没有 CLI 约定。缺失约定诊断保留这一事实，
不推断它是从未创建还是后来丢失。可以通过工作区文档入口继续任务，
或恢复原本应存在的约定；不要为消除诊断创建占位记录。
CLI 不从 Markdown 文件推断任务标题、验收或完成状态。

新检查点通过 `summary`、`next` 和 `blockers` 留存假设、观察与剩余工作，不再接受原来的可选
`loop` 输入。已经保存的版本 2 检查点仍可原样读取该元数据；它不授予权限或表示完成。
宿主负责迭代、预算和是否继续的决定。

`task list` 和不指定任务的 `status` 默认每页 50 条，`--limit` 可取 1–200；
256 KiB 内容预算可能使页面提前结束。把 `nextAfter` 传给 `--after NAME` 读取下一页，
直到返回 null。原样传递游标；异常磁盘名称会编码，避免损坏条目使翻页无法继续。
按 ID 字典序而非最近时间排列，顺序读取、限制内存中的名称数量；
文件系统并发变化不构成一致性快照。已知任务不必先列举，直接 `context ID`；
配置不可用时用 `task show ID`。

`task show` 返回当前约定、完整的最近交接及一页修订历史。其 `--limit` 与 `--after`
用于按文件名字典序翻页；默认 50 条、最多 200 条，修订内容预算为 256 KiB。
损坏、不可读或超出预算的修订分别记入 `issues`，不隐藏健康记录；超大记录保留在磁盘，
按报告路径直接查看。翻页与诊断不会修复、删除或批准历史。

`task list` 不依赖配置或源根可用性。配置有效时，源根不可用不隐藏已有上下文、附件或回执：
`context` 报告源错误，`evidence list` 将本地绑定标为未知，`reconcile` 返回未知适用性。
执行、新检查点与附件采集仍要求当前输入可用。任务结构无效需先修复；
引用不可读时，上下文的 `taskDigest` 为 null，核验适用性未知，仍可查看历史制品。
执行或采集新记录前须恢复访问。
已移除的源或检查引用也不隐藏历史观察或交接，只将当前适用性保留为未知；
新工作开始前，按当前配置修订约定。

即使配置无效或当前约定不可读，`evidence list` 仍可检查已存附件的身份与完整性，
并将本地绑定标为未知、说明原因。它不重建缺失约定，也不授予恢复操作的权限。

最新检查点损坏、不可读或身份不符时，`context` 返回 `reconcile-required`，
`changes` 中给出诊断且 `checkpoint: null`，不偷偷回退到更早记录。
重建当前事实后可显式保存新交接，其序号越过损坏项并保留原文件，返回 `previousCheckpointIssues`。
这只恢复续接，不修复损坏约定、不可读的检查点目录或遗留写锁。
