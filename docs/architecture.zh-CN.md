# 架构与边界

[English](architecture.md)

## 职责分配

用户需求与现有工程 → 宿主 Agent + `clinx-delivery` Skill → 已有代码、浏览器与平台工具。
需要确定性支持时再调用 CLI；CLI 不调用模型，不安装环境，不自动推进阶段。

| 产物                                  | 归属与作用                               |
| ------------------------------------- | ---------------------------------------- |
| `clinx.config.json`                   | 项目拥有的源范围、上下文索引与已审阅检查 |
| 原地图或 `clinx/system-map.md`        | 导航到真实源码，不复制平行数据库         |
| 原指南或 `clinx/local-guide.md`       | 实际操作与私有平台语义                   |
| `clinx/tasks/ID/contract.json`        | 结果、范围、不变量、决策、权限、验收条件 |
| 任务 `context`                        | 引用的本地方案，其内容参与任务绑定       |
| `checkpoints/NNNNNNNN.json`           | 输入绑定的续接说明，不表示完成           |
| `revisions/*.json`                    | 旧约定及原因、摘要，不回滚代码           |
| `.clinx/runs/UUID/receipt.json`       | 本地执行记录，未签名、未独立认证         |
| 同目录 stdout/stderr/XML              | 有界的原始执行输出                       |
| `.clinx/evidence/ID/UUID/record.json` | 观察者声明与复制附件，不是验收结论       |

模型由 `src/schema.ts` 定义，构建生成 JSON Schema。
CLI 额外检查交叉引用、唯一性和文件系统约束；只做 Schema 校验并不等价。
Markdown 保存推理，JSON 保存机器记录。支持 Skill、CLI 和 Schema，不提供独立 JavaScript SDK。

## 输入绑定与恢复

配置绑定规范化配置；任务绑定规范化任务及显式引用文件的内容；
源指纹绑定声明路径、内容和可执行位，排序确定。
执行记录保存前后指纹，核验时再检查当前输入和记录制品；检查点使用相同的约定/配置/源绑定。
操作会读取当前配置，不盲信内存里的旧索引。

绑定采用保守的整体范围：整份配置、任务和全部声明源均参与，即使本次只选部分检查。
某个不相关的声明源或检查定义变化，也可能使整份记录陈旧。核验一次读取一份执行记录，
不自动合并多次运行的通过项，也不计算检查级依赖。Agent 可以保留未受影响的工程改动，
但这不等于 CLI 自动确认旧证据仍适用。记录前选定真实相关范围，不为通过而隐瞒依赖。
记录还绑定所选声明：即使检查有重叠，修改 `--claim` 也不能把较窄的执行升级为更广验收。

输入列表必须明确，没有默认全量扫描。仅显式排除生效；直接指定的输入不能同时被排除。
目录名与 gitignore 不隐式改变范围。修改约定保留原 JSON，不抹去旧执行记录或把所有工作退回起点。

修订严格核对新约定与当前检查、引用文件；旧约定仅核对自身结构、内部关系和任务身份，
不要求已经过时的检查或方案路径仍可用。历史的 `previous` 保留原始 JSON 值；
`previousContractDigest` 是该 JSON 规范化后的摘要，不包含旧引用文件；
`nextDigest` 绑定新约定和当前引用。CLI 不使用今天的字节伪造历史输入绑定。
需要恢复方案历史内容时，沿用原工程的版本管理。损坏或身份不符的旧约定需要明确修复，
修订不是强制覆盖入口。

观察附件在验收计算之外，保留失败与不确定结果，不用新“通过”覆盖它们。
完整性与采集时本地绑定不表示真实目标版本或远端状态有效。

写操作使用项目级排他锁；新文件先写入并同步到同目录私有临时文件，再用排他硬链接发布最终文件名，
不覆盖已有目标，读取者不把临时文件当记录。写入与读取采用相同的每文件 8 MiB 上限。
文件系统需支持硬链接；不退化为不安全的覆盖，也不保证完整的掉电持久性。
修订先保存旧约定再替换指定文件。
初始化先查冲突，但多文件写入不是事务：I/O 错误可能留下部分文件，需检查后安全重试。
崩溃后不自动抢锁。详见[CLI 恢复](cli.zh-CN.md#恢复)。

任务发现逐项隔离错误。最新检查点损坏时显式报告并要求对账，不静默选择更早的说明；
明确创建新检查点会越过损坏序号，保留原文件。
记录访问与源根解析分开：源根不可用时，当前绑定未知，已有历史仍可读取。
执行和采集新绑定仍要求输入可用。详见[恢复](cli.zh-CN.md#恢复)。

## 结果格式与执行

`exit-code` 只说明命令是否退出零，不推断运行过测试。
`junit` 处理有界 XML，拒绝 DTD/实体、计数矛盾、重复身份和未支持的套件级失败/跳过，
区分失败与跳过，检查预期用例和最低数量。支持 Surefire 与 Node 报告的一部分明确结构，
不是所有 JUnit 方言；不支持的结果保持不确定。递归处理 `testsuite` 与 `testsuites`，
拒绝未知结构子元素。执行记录仅保存汇总计数，逐用例身份保留在原始 XML，
核验时重新解析，不再重复存储膨胀后的用例集合。

文件报告必须在本次命令中创建或改写，随后复制到记录目录。
这防止误用旧报告，不防恶意脚本重写旧 XML。
命令按 argv、`shell: false` 执行，原样保留空参数和纯空白参数，要求程序名非空白；
所有参数均禁止 NUL。显式调用 shell 仍是任意代码。
单项目顺序执行减少共享报告干扰，不是分布式调度器。
可执行文件保持原调用路径，包括符号链接与基于子进程 cwd 的 PATH。

## 限制

- 执行支持 macOS/Linux、Node 22.16+；方法与 Skill 不要求目标工程使用 Node。
- 不是沙箱：继承 PATH、环境、凭据、权限与网络；副作用声明不是强制权限策略。
- 有文件写权限者可伪造记录及哈希，无远端认证、签名导入或防篡改审计保证。
- 未声明或被排除的相关输入不在证据范围；依赖安装目录、工具链与远端状态不自动绑定。
- 每文件最多 8 MiB，每源 128 MiB、50,000 个条目（含目录），拒绝符号链接输入。
  大工程应按真实相关范围选择输入，不为通过而隐瞒依赖。
- 两次采样之间修改又恢复可能无法发现；`current` 不代表远端或整个工具链未变。
  CLI 版本及已记录运行时变化需要重验，但并非每个被调用工具的环境快照。
- 每个输出流最多 2 MiB；被截断的 stdout JUnit 不确定。日志不自动脱敏，不能公开 `.clinx`。
- JUnit 文件路径为字面路径，不展开 glob；跳过与缺少预期用例不支持当前验收。
- 不同项目根的锁不协调兄弟源、IDE、人工操作或远端任务，需检查输入变化。
- 无内置浏览器自动化、企业接口、审批或自动发布；外部条件在 CLI 中保持未决。
- 文件系统并发攻击、脱离进程组的恶意子进程、强制终止或系统崩溃不在完整隔离保证内。

## 实现选择

TypeScript/Node 提供 CLI 运行时，JSON 定义可验证记录，Markdown 保存使用者与 Agent 指引。
执行复用项目已有命令。CLI 保持少量结果适配器，其他原生格式仍由项目工具负责。
新增接口需要具体用例、稳定边界与行为测试，详见[贡献指南](../CONTRIBUTING.zh-CN.md)。
